# G-Link 酒店接口功能测试用例

版本：1.0  
日期：2026-07-30  
测试环境：G-Link `sandbox`  
契约依据：`docs/swagger/glink-api.json`（2026-04-24）  
范围：功能测试，不包含性能、压力、并发容量和响应时间测试

## 1. 测试目标

验证分销系统使用开放平台官方沙箱测试酒店，完成以下真实业务链路：

```text
官方测试酒店
→ /hotel/lowestPrice
→ /booking/productDetails
→ /booking/availabilityCheck（首次）
→ 本地订单落库
→ /booking/availabilityCheck（提交前二次）
→ /booking/createOrder
→ /booking/payOrder
→ /notify/orderStatus（主链路）
→ /order/orderDetail（补偿）
→ /order/cancelOrder
```

所有供应商请求必须只发送 Swagger 定义的业务字段，并使用当前 `sandbox`
App Key/Secret 生成 `X-OP-*` 签名。

截图中的重复酒店 ID 必须自动去重。执行前从开放平台“酒店测试数据”页面补齐完整清单。

自动选择规则：

1. 仅在 `FCG_MODE=sandbox` 且 `FCG_ENV=sandbox` 时允许使用官方测试酒店清单。
2. 生产环境禁止加载官方测试酒店清单。
3. 入住日期从当前日期后 7～30 天内自动选择，离店日期为入住后 1 天。
4. 每批最多向 `/hotel/lowestPrice` 提交 10 个酒店 ID。
5. 逐批筛选返回有效起价的酒店。
6. 对有起价的酒店调用 `/booking/productDetails`。
7. 优先选择 `bookType=1` 产品。
8. 分别覆盖预付、到付和不同取消政策产品。
9. 找到首个可试订产品后用于支付订单用例；另创建一笔未支付订单用于取消用例。
10. 每次执行使用新的 `coOrderCode`、nonce、Idempotency-Key，禁止复用历史下单标识。

## 3. 测试前置条件

- G-Link 沙箱凭证已配置且鉴权成功。
- 系统时间误差不超过 5 分钟。
- `FCG_SANDBOX_HOTEL_SIMULATION=false`。
- 数据库迁移完成。
- 沙箱企业授信或测试支付条件可用。
- 前端与 API 服务正常运行。
- Webhook 真实推送测试前已配置公网 HTTPS 地址。
- 测试联系人、入住人使用平台允许的测试信息。

## 15. 测试证据要求

每个真实供应商接口用例记录：

- 用例编号。
- 测试酒店 ID、入住/离店日期、房间数。
- 接口短路径。
- HTTP 状态与平台业务码。
- `request_id`、`trace_id`、`downstream_request_id`。
- 本地订单号、`coOrderCode`、`fcOrderCode`。
- 供应商原始状态值与本地映射状态。
- 通过/失败/阻塞结论。
- 失败时的业务错误码和脱敏错误信息。

禁止记录：

- App Secret。
- 完整签名原文。
- 真实客户证件、银行卡、密码等敏感数据。

## 16. 总体通过标准

P0 用例必须全部通过：

1. 至少一个官方测试酒店成功返回起价和 `bookType=1` 实时产品。
2. 首次及二次试订均使用实际房间数。
3. 完成一笔真实沙箱创建和支付订单并获得 `fcOrderCode`。
4. 完成一笔真实沙箱未支付订单取消。
5. 状态推送签名与幂等通过；若公网推送暂不可用，必须标记为阻塞，不能以本地模拟替代真实推送。
6. 支付后补偿查单正确，确认或取消后停止查询。
7. 全流程不存在模拟订单冒充供应商订单。
8. 自动测试、类型检查和生产构建全部通过。
