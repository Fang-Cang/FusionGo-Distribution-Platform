# FusionGo 全系统功能审计与修复报告

审计日期：2026-08-06  
审计环境：本地前端、Node API、SQLite 文件数据库、FCG Sandbox  
审计原则：只展示真实接口或真实数据库数据；未接入的能力必须禁用或明确标注，不得以模拟成功代替。

## 1. 结论

本轮已完成酒店、机票、订单、账户、客户、定价、财务和全局导航的功能、业务逻辑与主要桌面交互审计。沙箱环境可以用于继续功能验收，但当前版本仍不满足生产发布条件，生产身份认证、生产级数据层、真实收单/授信、深层页面完整多语言等 P0/P1 项必须在上线前关闭。

本轮没有创建、支付或取消新的上游订单。供应商验证仅执行酒店与机票查询类只读接口。

## 2. 本轮发现并修复的问题

| 级别 | 模块 | 问题 | 修复结果 |
| --- | --- | --- | --- |
| P0 | 经营总览 | 今日销售额、增长率、趋势和最近订单含静态演示数据 | 改为读取本地业务数据库；今日无交易时显示 0；按币种分别展示，不再伪造环比 |
| P0 | 权限边界 | 游客可直接调用验房、机票验价及非生产维护接口 | 增加服务端认证拦截；游客仍可查询，但不能进入验价、下单和维护操作 |
| P0 | 支付 | 银行卡通道未接真实收单，却可能表现为支付成功 | 后端统一拒绝 `card`；前端禁用并说明未开通，仅保留已接入的企业授信流程 |
| P0 | 机票金额 | 总价可能按成人单价乘总人数计算，儿童票会产生错误金额 | 优先使用 F-Link 返回的真实订单总价，只有上游缺失时才使用兼容回退 |
| P0 | 酒店查询 | 可能接受过去日期、退房早于入住、成人少于房间数、儿童年龄缺失 | 前后端同时校验日期、房间/成人关系、儿童数量与年龄数组一致性 |
| P0 | 机票查询 | 可能接受同机场、过去日期、返程早于去程、婴儿多于成人或旅客超过 9 人 | 前后端增加完整行程和旅客组成校验 |
| P1 | 酒店旅客 | 搜索条件缺少儿童及儿童年龄，无法传递真实入住组成 | 增加儿童数量和 0–17 岁逐人年龄，并贯穿查询上下文 |
| P1 | 机票旅客 | 搜索和预订未完整区分成人、儿童、婴儿 | 增加三类旅客、年龄约束、婴儿关联成人和逐旅客表单 |
| P1 | 订单中心 | 状态筛选按钮仅展示，无真实筛选/数量/加载与空态 | 已接入真实筛选、计数、加载、错误和多语言空态 |
| P1 | 账户与全局 | 额度、通知、登录记录和双重验证含硬编码或虚假能力提示 | 额度读取财务接口；通知读取待处理真实订单；虚假登录审计移除；MFA 明确未接入并禁用 |
| P1 | 国际化 | 客户、定价、财务一级页面在英文模式仍显示中文 | 已补齐这些一级运营页面的中英文文案 |
| P1 | 用户体验 | 首页房间/旅客浮层向下展开时被首屏容器裁切 | 桌面端改为向上展开；移动端固定在 16px 安全边距内 |
| P1 | 交互真实性 | 价格提醒、附加服务等未接入能力可被误解为真实功能 | 未接入项禁用并明确标注，不再制造成功反馈或计费 |
| P0 | 注册与权限 | 新用户没有注册入口；注册后若沿用验收账号能力会越权成为管理员 | 新增持久化注册、邮箱密码登录和会话失效；新用户默认普通成员，隐藏并在服务端禁止经营、客户、定价和财务权限 |

## 4. 功能与用户体验验证

- 默认进入酒店预订；游客仅看到酒店和机票查询，并显示登录入口。
- 登录后可进入订单、经营总览、客户、定价、财务及账户设置，可退出登录。
- 酒店房间/成人/儿童选择、儿童年龄、日期边界和搜索参数均可操作。
- 机票成人/儿童/婴儿选择、往返日期、逐旅客资料和价格汇总逻辑已覆盖。
- 订单中心的全部、待支付、处理中、已确认、售后状态可筛选。
- 英文模式下，全局导航以及客户、定价、财务一级页面已验证为英文。
- 币种换算服务不可用时保留供应商原币并显示错误，不静默使用虚假汇率。
- 玻璃浮层在支持模糊的浏览器使用浅色磨砂材质；不支持时使用不透明降级；保留键盘焦点、禁用态、错误态与减少动效设置。

## 6. 上线前仍未关闭的问题

| 级别 | 阻塞项 | 当前风险 | 关闭标准 |
| --- | --- | --- | --- |
| P0 | 生产身份与租户权限 | 当前生产模式没有真实用户会话，服务端会拒绝用户接口；不能以沙箱快捷登录上线 | 接入企业 SSO/OIDC，会话、租户隔离、RBAC、退出、审计和高风险操作二次确认通过 |
| P0 | 生产数据库与并发任务 | SQLite 只适合当前本地单机验收，多实例下无法满足事务、锁、任务和高可用要求 | 切换 PostgreSQL、Redis/任务队列、outbox，完成备份恢复和多实例验证 |
| P0 | 真实支付/授信 | 银行卡未接收单，企业授信仍需与正式财务系统闭环 | 支付回调、额度冻结/扣减/恢复、退款、对账和幂等全部通过 |
| P0 | 上游生产准入 | 当前证据主要来自 Sandbox | 生产凭证、真实小额酒店/机票订单、支付、确认/出票、取消/退改与回调闭环 |
| P1 | 深层页面多语言 | 酒店/机票结算、订单详情及售后仍存在中文固定文案 | 全站文案入字典，英文逐页人工验收，无混合语言 |
| P1 | 币种换算依赖 | 外部汇率服务超时会阻止展示币种换算 | 使用受监控、可审计的汇率源与缓存，明确报价币种和结算币种；禁止静默回退假汇率 |
| P1 | 企业能力 | 修改密码、MFA、信用调整、消息投递仍缺真实企业服务 | 分别接入身份、短信/验证器、财务审批、邮件/站内信服务及审计日志 |
| P1 | 移动端实机验收 | 本轮通过响应式 CSS 审查，未形成完整多机型截图证据 | iOS/Android 主流尺寸完成酒店、机票、订单和浮层全流程人工回归 |
| P1 | 供应商异步时效 | 出票、改签、退票等依赖供应商异步处理 | 明确 SLA、超时告警、低频补偿、人工工单与终态对账 |

## 7. 发布判断

- 本地/Sandbox 功能验收：可继续。
- 测试环境部署：可以，但必须使用测试域名、Sandbox 凭证、隔离数据库，并清晰标注“测试环境”。
- 生产发布：暂不通过。第 6 节 P0 项全部关闭且重新完成端到端验收后才能放行。
