## 最高优先级缺陷

### P0：机票增值服务未进入订单金额

- 支付页：`¥1,269`
- 订单创建、支付、确认和数据库：`¥861`
- 影响：用户看到的应付金额与实际订单金额不一致，无法正确结算行李、选座和保障。
- 建议：把增值服务作为本地商品明细持久化，明确哪些由 F-Link 销售、哪些由分销系统销售；创建本地支付单时使用完整应付金额，并分别记录机票供应金额和本地附加服务金额。

### P1：机票状态从已出票变为已取消

- 支付后详情首次映射为 `TICKETED`
- 再次查询上游后变为 `CANCELLED`
- 建议：保存每次 F-Link 原始状态码和时间，核对 `flinkStatus` 映射；订单终态变更必须进入异常队列，不能静默覆盖。

### P1：多个可见控件没有业务行为

- 酒店：住客选择、地图、排序、酒店筛选、房型筛选
- 机票：往返/多程、低价日期、筛选、降价提醒、排序
- 公共：语言、币种、通知、下载类按钮、在线值机
- 建议：未实现功能在测试版本中应禁用并显示“即将开放”，不要呈现为可点击按钮。

### P1：酒店与票价品牌的选中样式错误

- 原生 radio 已改变
- 外层 `selected` 类仍固定在默认选项
- 建议：改为受控状态，并让价格、权益、CTA 金额和高亮统一由选中对象派生。

## UX 与可访问性结论

确认良好：

- 搜索、验价、支付均有 loading 和 disabled 状态。
- 错误使用 `role=alert`，结果状态使用 `aria-live`。
- 主要字段有可读标签。
- 票价浮层有 `role=dialog` 和 `aria-modal=true`。
- 键盘焦点有明显 2px indigo 轮廓。
- 酒店模拟房态有明确警告，不会与真实库存混淆。
- 390px 下没有横向溢出。

主要风险：

- 票价浮层没有可见的 Escape 关闭和焦点锁定逻辑。
- 多个筛选/分段按钮缺少 `aria-pressed` 或选中状态。
- 酒店住客按钮没有 `aria-expanded`，且没有弹层。
- 移动端支付摘要排在表单之前，阅读和操作顺序不自然。
- 结果列表 180 张卡片一次渲染，影响扫描效率和移动端性能。
- 截图和 DOM 检查不能证明完整 WCAG AA；颜色对比度仍需自动化扫描或设计令牌计算。
- 原生日期选择器的弹出日历无法在当前自动化表面完整检查；已验证默认日期可提交，但未验证每个系统原生日历状态。
